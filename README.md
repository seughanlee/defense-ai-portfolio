# 방산 AI 엔지니어 포트폴리오 — "AI의 판단을 믿어도 되는가"

L-SAM 같은 다기능레이더(MFR) 기반 대공방어 체계를 만드는 기업(LIG넥스원, 한화시스템, 한화에어로스페이스 등)의 AI 엔지니어 직무를 목표로 한 소형 프로젝트 모음입니다.
**공개 자료와 합성(시뮬레이션) 데이터만 사용**하며, 실제 체계 데이터와 보안 사항은 다루지 않습니다.

방산 체계에서 AI가 틀리는 것보다 더 위험한 경우는 **틀리면서 확신하는 것**입니다. 그래서 모든 프로젝트는 정확도에서 멈추지 않고 같은 질문으로 끝납니다.
> 이 모델은 언제 자기 확신과 다르게 틀리는가? 그것을 어떻게 드러내고, 어떻게 막는가?

## 관통 주제: AI의 자기 확신이 틀리는 순간
세 프로젝트에서 같은 현상을 서로 다른 문제로 확인했습니다.

| 프로젝트 | 확신하며 틀린 상황 | 어떻게 드러냈나 | 대책과 효과 |
|---|---|---|---|
| P1 추적 | 설계 범위 밖 급선회(4~6g)에서 오차 1.3 km, 필터는 여전히 자신만만 | NEES(추정 오차와 실제 오차의 비율)가 4000 이상 | 고잡음 예비 모델 추가. 6g 오차 443 m → 247 m, 공칭 성능 4% 손해 |
| P2 식별 | 처음 보는 옥토콥터를 85% 헥사콥터로 판정 | 미지 표적 점수 4종 모두 실패 → 선형 탐침으로 "신호에 로터 개수 정보가 거의 없음" 확인 | 억지로 맞히지 않고 덜 구체적으로 답하기 (예측 집합, 계층형 출력). 맞는 답은 주지만 알아채지는 못함 |
| P3 정비 | 처음 보는 고장 모드에서 적중률 0.655, 모델 분산은 오히려 감소 | 엔진별·구간별 적중률, 위험 방향 이탈률 | 모델 없는 입력 범위 감시로 오경보 0%, 고장 임박 구간 100% 검출 |

**공통 결론:** 모델의 자기 평가(분산, softmax 확률, 공분산)는 학습 범위 안에서만 믿을 수 있습니다. 범위 밖을 지키려면 **모델과 독립된 감시 장치**가 필요합니다.

## 방산 AI 직무 역량과 근거
| 역량 | 일반 IT AI 직무와의 차이 | 이 저장소의 근거 |
|---|---|---|
| 신호처리·추적 기초 | 칼만필터, 레이더 신호 모델 같은 **도메인 수학**이 기본 소양 | P1 IMM·CT-EKF 직접 구현과 야코비안 검증, P2 마이크로도플러 물리 시뮬레이터 |
| 신뢰성·검증 (V&V) | 정확도보다 **일관성, 최악 사례, 보장**이 중요 | P1 NEES, P2 보정·conformal 집합, P3 conformal 구간과 엔진별 적중률 |
| 설계 범위 밖 강건성 | 체계 요구사항은 평균이 아니라 최악의 경우로 정의 | P1 1~6g 시험, P2 학습 범위 밖 SNR, P3 센서 고장·미지 고장 모드 |

| 운용 의사결정 연결 | 모델 지표를 비용과 위험으로 번역 | P3 정비 정책 비용 시뮬레이션, P5 품질 비용 계획 |
| 문서화와 추적성 | 무기체계 SW 개발 절차의 요구사항·시험 문서 | 사전 등록한 평가 설계, 결과를 본 뒤 바꾼 점의 기록, 단계별 [CHANGELOG](CHANGELOG.md) |

## 작업 원칙
모든 프로젝트에 같은 규칙을 적용합니다. 면접관이 결과를 믿을 수 있게 하기 위한 장치입니다.

| 원칙 | 구체적인 방법 | 실제로 잡아낸 사례 |
|---|---|---|
| 가설을 먼저 적는다 | 실험 전에 가설과 판정 기준을 코드 docstring이나 평가 문서에 고정 | P3 H1(딥러닝 우세), P2 v2 해상도 가설이 반증됨을 그대로 보고 |
| 결과를 본 뒤의 변경은 따로 표시한다 | "사후 분석" 표시, `EVALUATION.md`에 변경 기록 | P2 v2 빈 집합 대체, 깨끗한 보정 재확인 |
| 평가 데이터는 한 번만 쓴다 | 튜닝 시드와 평가 시드 분리(P1), 공식 test 1회(P3) | P3에서 val과 test의 모델 순위가 뒤집힘을 확인 |
| 보정 데이터는 깨끗해야 한다 | 학습·모델 선택·온도 조정에 쓴 데이터로 보정하지 않음 | P2 v2에서 val 보정 시 보장 목표를 1~7%p 놓침 → 원칙으로 승격 |
| 표본 크기는 독립 단위로 센다 | 행 수가 아니라 엔진 수, 불량 건수 | P3 CNN 과적합 원인, P5 보장에 필요한 불량 수 계산 |
| 평균 뒤에 숨은 실패를 찾는다 | 클래스별, 구간별, 조건별로 나눠 보기 | P2 쿼드콥터 적중률 0.72, P3 열화 시작 구간 미달 |
| 막힌 길은 짧게 확인한다 | 긴 재학습 전에 몇 분짜리 진단 | P2 v2 정보량 진단으로 재학습 없이 방향 전환 |
| 재현할 수 있어야 한다 | 시드 고정, 스크립트 하나로 결과 파일과 그림 생성, 데이터 출처와 해시 기록 | 리팩터링 후 이전 수치 재현 확인 (P1, P2 시뮬레이터) |

## 진행 순서를 이렇게 잡은 이유
1. **추적(P1):** 레이더 체계 엔지니어와 대화할 공통 언어입니다. AI 이전에 갖춰야 하는 기초입니다.
2. **식별(P2):** 딥러닝, 불확실성, 임베디드 배포를 한 문제에서 보여줍니다.
3. **PHM(P3):** 방산 업계에서 AI 실적용 사례가 가장 많은 분야이고, 공개 데이터셋으로 바로 시작할 수 있습니다.
4. **품질(P4, P5):** 방산 생산 현장의 검사와 공정 관리입니다. 정비(P3)와 함께 "AI로 운용·생산 품질을 끌어올렸다"는 이야기를 완성합니다.
5. **RAG(P6):** 폐쇄망 LLM 수요가 커지고 있고, 일반 AI 직무와도 겹치는 기술입니다.

### 환경 설정
```bash
python -m venv .venv
.venv\Scripts\activate
pip install torch --index-url https://download.pytorch.org/whl/cpu
pip install -r project1_radar_tracking/requirements.txt -r project2_microdoppler/requirements.txt -r project3_phm/requirements.txt
```
개발 환경: Windows 10, Python 3.14, CPU 전용 (8스레드). GPU 없이 모든 실험을 수 분~수십 분 안에 재현할 수 있게 규모를 맞췄습니다.
