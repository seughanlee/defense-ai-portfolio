# PatchCore Ablation Study (v1)

> 결과 절은 `results/ablation/`의 CSV에서 옮겨 적습니다. 실행하지 않은 조합은 `NOT_RUN`으로 표시합니다. 용어는 [GLOSSARY](GLOSSARY.md) 참고.

## 1. 질문
PatchCore를 CPU 검사 서비스로 운영할 때, 다음 네 가지 설계 선택이 **검출 품질**(image AUROC, pixel AUROC, AUPRO)과
**운영 비용**(batch-1 P95 지연, 최대 메모리)을 어떻게 바꾸는가?

| 요인 | 수준 | 기준값 (B0) |
|---|---|---|
| 백본 | resnet18 / resnet50 / wide_resnet50_2 (모두 torchvision 가중치), wide_resnet50_2 (timm `racm` 가중치) | wide_resnet50_2.tv_in1k |
| 특징 레이어 | layer2 / layer3 / layer2+3 / layer1+2+3 | layer2+3 |
| 메모리 뱅크 샘플링 | k-center greedy 1% / 10% / 25%, random 10%, 전체(100%) | k-center greedy 10% |
| 입력 크기 | 192 / 256 / 320 px | 256 |

## 2. 사전 등록
- 계획 파일: [`ml/ablation/ablation_v1.yaml`](../ml/ablation/ablation_v1.yaml), SHA-256 `d26635b2eb71…` (2026-10-12 09:50 UTC, **MVTec 결과가 하나도 나오기 전**)
- 모든 결과 JSON에 계획 파일 해시를 기록합니다. 실험 도중 계획이 바뀌면 해시 불일치로 드러납니다.
- 설계: 기준값(B0)에서 **한 번에 한 요인만** 바꿉니다. 요인 사이의 상호작용은 이 설계로 알 수 없습니다.
- 카테고리: metal_nut, screw, capsule, transistor. 카테고리마다 모델을 따로 학습합니다.

## 3. 데이터 분리와 선택 규칙
| 분할 | 출처 | 용도 |
|---|---|---|
| fit | 공식 `train/good`의 80% | 메모리 뱅크 |
| val (정상) | 공식 `train/good`의 20% (seed 42, 모든 실험에 동일) | 이미지 임계값 보정, 검증 지표, 지연시간 측정 |
| val (합성 이상) | val 정상 이미지 1장마다 합성 결함 1개 (`cutpaste` / `scar` / `noise_blob`, seed 1234) | **모델 선택 지표** |
| test | 공식 `test/*` | 보고 전용 |

**왜 합성 이상이 필요한가.** 공식 분할에서 결함 이미지는 test에만 있습니다. 결함이 없는 검증셋으로는 AUROC를 계산할 수 없고,
test로 고르면 test 성능이 낙관적으로 부풀려집니다. 그래서 메모리 뱅크가 본 적 없는 val 이미지 위에 결함을 합성해 선택 지표로 씁니다.
이 대리 지표가 실제 결함 순위와 얼마나 맞는지는 **Spearman 순위상관으로 따로 측정해 보고**합니다 (§6).

**선택 규칙 (결과 전에 고정):**
1. 각 설정의 검증 image AUROC를 seed 평균 → 카테고리 평균합니다.
2. 최고값과 0.01 이내인 설정 중 평균 P95 지연이 가장 짧은 설정을 고릅니다.
3. test 지표는 선택이 끝난 뒤에 읽습니다. test 결과를 보고 규칙이나 설정을 바꾸지 않습니다.

이미지 임계값(정상 val 점수의 0.99 분위수)도 val에서만 정합니다. test의 F1·오경보율은 이 임계값을 그대로 적용한 값입니다.

## 4. 측정 방법
| 지표 | 정의 |
|---|---|
| image AUROC | 이미지 점수 기준 정상/결함 순위 |
| pixel AUROC | 모든 test 픽셀 (정상 이미지 = 결함 픽셀 없음) |
| AUPRO | FPR ≤ 0.3까지 PRO 곡선 면적, 0~1 정규화, 8-연결 영역. **MVTec 공식 평가 코드와 4개 사례에서 소수점 5자리까지 일치** ([crosscheck](../results/aupro_crosscheck.csv)) |
| P95 지연 | batch 1, 디코딩된 이미지 → 전처리 + 백본 + 최근접 탐색 + heatmap. 워밍업 3회 뒤 30회 측정. CPU 4스레드 |
| 최대 메모리 (serve) | 새 프로세스에서 아티팩트 로드 + batch-1 추론 30회 직후의 peak working set |
| 최대 메모리 (fit) | 학습 프로세스 전체의 peak working set (특징 추출 + 샘플링 + 임계값 보정) |

- 픽셀 지표는 모델 입력 해상도에서 계산합니다. 그래서 입력 크기가 다른 설정끼리는 픽셀 지표를 계산하는 해상도도 다릅니다 (§7).
- 학습(fit)과 평가는 각각 새 프로세스에서 실행합니다. peak 메모리는 프로세스 단위 최고 기록이라 되돌릴 수 없기 때문입니다.
- 샘플링 seed를 고정했기 때문에 같은 seed로 다시 돌리면 같은 메모리 뱅크가 나옵니다 (테스트로 확인). 무작위성의 크기는 B0와 random 10%를 seed 3개로 돌려 측정합니다.

## 5. 결과
**진행: 64회 중 1회 실행** (2026-10-13). 나머지 63회는 CPU 약 19시간이 걸려 사용자 요청으로 보류 중이며 `NOT_RUN`입니다.
전체 표(실행 안 한 칸 포함)는 [`results/ablation/tables.md`](../results/ablation/tables.md), 원자료는 `runs.csv`·`summary.csv`입니다.

### 5.1 시험 실행: B0 · metal_nut · seed 0
본 실행 전에 실데이터에서만 드러나는 문제를 찾고 소요 시간을 추정하려고 1회를 먼저 돌렸습니다. 사전 등록 계획의 한 회차이므로 본 실행에서 그대로 재사용됩니다.

| 구분 | 지표 | 값 |
|---|---|---|
| 검증 (정상 44 + 합성 결함 44) | image AUROC / pixel AUROC / AUPRO | 0.9985 / 0.9972 / 0.9867 |
| test (정상 22 + 결함 93) | image AUROC / pixel AUROC / AUPRO | 0.9985 / 0.9894 / 0.9420 |
| test, 검증 임계값 적용 | 정상 오경보율 / 결함 검출률 / F1 | 4.5% (1/22) / 96.8% / 0.978 |
| 비용 | batch-1 지연 평균 / P95 | 744 ms / 838 ms |
| 비용 | 최대 메모리 서비스 / 학습 | 1,179 MB / 1,806 MB |
| 비용 | 학습 시간 (특징 추출 / coreset 선택) | 829 s (84 s / 693 s) |

### 5.2 시험 실행에서 발견한 것
1. **검증 대리 지표의 상한 효과.** 합성 결함 image AUROC가 0.998로 거의 1입니다. 다른 설정들도 모두 1 근처라면 선택 규칙 1단계가 설정을 구분하지 못하고,
   사실상 2단계(가장 짧은 지연)로 결정됩니다. 사전 등록 규칙은 그대로 적용하되, 이 상한 효과와 덜 포화된 검증 AUPRO(0.987)를 함께 보고합니다.
   규칙을 결과에 맞춰 바꾸지 않습니다.
2. **소요 시간.** coreset 선택이 학습 시간의 84%입니다. k-center greedy 비용은 대략 (coreset 비율) × (패치 수)²에 비례해,
   패치가 많은 설정(screw: 학습 이미지 256장, R-320: 이미지당 1,600 패치, S-kc025)이 특히 깁니다. 측정값으로 보정한 추정은 전체 약 19시간입니다.
3. **오경보율.** 목표(약 1%)보다 높은 4.5%였지만 정상 test 이미지가 22장뿐이라 1장 차이입니다. 검증셋 크기에 따른 임계값 흔들림은 별도 분석으로 다룹니다.
4. **Hugging Face Hub 접속.** 가중치가 캐시에 있어도 로드할 때마다 Hub에 요청을 보냈습니다. 장시간 실행 중 네트워크 문제로 실패하지 않도록 실행기를 기본 오프라인(`HF_HUB_OFFLINE=1`)으로 바꿨습니다.

## 7. 한계
- 한 번에 한 요인만 바꾸는 설계라 요인 간 상호작용(예: 큰 입력 + 작은 백본)은 다루지 않습니다.
- 카테고리 4개, B0·random 외에는 seed 1개입니다. seed 편차보다 작은 차이는 결론으로 쓰지 않습니다.
- 합성 결함은 실제 결함 분포가 아닙니다. 전경 마스크는 테두리 색과 다른 픽셀이라는 단순 규칙입니다.
- 지연·메모리는 이 노트북 한 대(i5-1135G7, Windows 10, CPU 4스레드)에서 측정한 값입니다. 다른 작업이 동시에 돌면 값이 흔들립니다.
- 픽셀 지표는 원본 해상도가 아니라 모델 입력 해상도에서 계산했으므로 논문 수치와 직접 비교하지 않습니다.
