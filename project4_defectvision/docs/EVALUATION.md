## 평가 규칙
1. 임계값과 하이퍼파라미터는 정상 검증셋(train/good의 20%)으로만 정합니다. 공식 test split의 결과를 보고 설정을 바꾸지 않습니다.
2. 임계값에 의존하는 지표(precision, recall, F1, confusion matrix, IoU)는 항상 사용한 임계값과 함께 기록합니다.
3. 픽셀 지표는 **모델 입력 해상도(기본 256 px)** 에서 계산합니다. 원본 해상도 평가와 다르므로 논문 수치와 직접 비교하지 않습니다.
4. IoU는 정답 마스크가 있는 결함 이미지에서만 평균합니다. 정상 이미지의 오검출은 이미지 단위 오경보율로 따로 봅니다.
5. 실행하지 않은 실험은 수치 대신 `NOT_RUN`으로 둡니다.

## 지표
| 수준 | 지표 | 구현 |
|---|---|---|
| 이미지 | AUROC, Average Precision | scikit-learn |
| 이미지 | precision / recall / F1 / 정상 오경보율 / confusion matrix @ 임계값 | `metrics.image_metrics` |
| 픽셀 | pixel AUROC | scikit-learn (전체 픽셀) |
| 영역 | AUPRO (FPR ≤ 0.3, 0~1 정규화) | `metrics.aupro` — 8-연결 영역 단위 겹침, 모든 점수를 임계값으로 쓰는 정확 계산. MVTec 공식 평가 코드와 일치 확인 (`scripts/crosscheck_aupro.py`, [결과](../results/aupro_crosscheck.csv)) |
| 픽셀 | mean IoU @ 픽셀 임계값 | `metrics.mean_iou` |
| 운영 | 모델 로드 시간, batch-1 지연 평균/p50/p95, 처리량 | `evaluate.py` (워밍업 2회 제외, 디코딩 후 시간) |

지표 함수 검증 (pytest): 완벽한 예측 → AUROC·AUPRO·IoU = 1, 무작위 map → AUPRO ≈ 0.15 (이론값 FPR 한계 0.3의 절반), 한 클래스만 있으면 `None`.

## 합성 스모크 테스트 기록 (성능 근거 아님)
2026-10-12, 랜덤 백본(`pre_trained=false`), 64 px, 합성 원판 20장 학습(fit 16 / val 4), test 12장.
- 파이프라인이 학습 → 보정 → 저장 → 로드(해시 검증) → 평가 → 패널 생성까지 끝까지 동작함을 확인했습니다.
- 관찰: 순위 지표는 높았지만 정상 6장 중 4장이 오경보였습니다. **검증 정상 이미지가 4장뿐이라 0.99 분위수 임계값이 낮게 잡힌 것**이 원인입니다.
  MVTec에서도 검증셋이 수십 장 수준이므로 같은 문제가 생길 수 있습니다. Phase 5에서 검증셋 크기에 따른 임계값 변동을 부트스트랩으로 측정합니다.

## 임계값 안정성 (metal_nut · B0 · seed 0, 2026-10-13)
질문: 정상 검증 이미지 몇십 장으로 정한 임계값의 오경보율을 믿어도 되는가? (용어: [GLOSSARY](GLOSSARY.md) — 분위수, 부트스트랩, FPR)
코드 `ml/evaluation/threshold_stability.py`, 결과 [`results/threshold_stability/`](../results/threshold_stability/). test는 결과를 보고하는 데만 썼고 임계값은 바꾸지 않았습니다.

**1) 이론값 (분포 가정 없음).** 검증 정상 점수 n개의 0.99 분위수를 임계값으로 쓰면, 새 정상 이미지가 그 값을 넘을 확률은
순서통계량(점수를 줄 세운 k번째 값)의 성질상 Beta(n+1−k, k)를 따릅니다. 정상 이미지들이 같은 분포에서 나온다는 가정만 필요합니다.

| 검증 정상 이미지 수 | 기대 오경보율 | 90% 상한 |
|---|---|---|
| 10 | 9.1 – 18.2 % | 39.4 % |
| 20 | 4.8 – 9.5 % | 21.6 % |
| 30 | 3.2 – 6.5 % | 14.9 % |
| **44 (현재)** | **2.2 – 4.4 %** | **10.3 %** |

**이름은 "99% 분위수"지만 검증 이미지가 44장이면 기대 오경보율은 1%가 아니라 2.2~4.4%입니다.** 실측 test 오경보율 4.5%(정상 22장 중 1장)는 이 범위와 맞습니다.
목표 1%를 지키려면 검증 정상 이미지가 수백 장 필요하거나, 분위수를 더 보수적으로 잡아야 합니다 (검출률과 맞바꿈).

**2) 부트스트랩 (5,000회).** 검증 점수를 다시 뽑았을 때:

| 검증 크기 | 임계값 5–95% | test 오경보율 중앙값 (5–95%) | test 검출률 중앙값 (5–95%) |
|---|---|---|---|
| 10 (부분추출) | 1.822 – 2.014 | 9.1 % (0 – 31.8 %) | 100 % (96.8 – 100 %) |
| 20 (부분추출) | 1.873 – 2.008 | 9.1 % (0 – 13.6 %) | 100 % (96.8 – 100 %) |
| 44 (복원추출) | 1.890 – 2.026 | 4.5 % (0 – 9.1 %) | 96.8 % (96.8 – 100 %) |

저장된 임계값 1.9856은 다시 계산한 검증 점수에서 정확히 재현되었습니다 (추론 결정성 확인).

**3) 실패 사례.** 정상 test 점수 최고 2.002, 결함 test 점수 최저 1.972 — 두 분포가 겹치는 좁은 띠에서만 판정이 틀립니다.

| 이미지 | 점수 | 판정 | 비고 |
|---|---|---|---|
| good/016 | 2.0016 | 오경보 | 임계값보다 0.016 높음 |
| color/004 | 1.9855 | 미검출 | 임계값보다 **0.0001** 낮음 — 색 결함은 형태 변화가 없어 패치 특징 차이가 작을 수 있음 (가설, 미검증) |
| bent/007 | 1.9797 | 미검출 | |
| scratch/022 | 1.9715 | 미검출 | |

실무적 시사점: 임계값 근처 점수는 "자동 합격/불합격" 대신 **사람 재검사 구간**으로 두는 것이 안전합니다 (예: 부트스트랩 5–95% 구간 1.89–2.03).
이 구간 설계는 아직 구현하지 않았습니다.

## 강건성 시험 계획 (Phase 5)
| 변형 | 가정 | 한계 |
|---|---|---|
| 밝기 ±, 감마 | 조명 변동은 결함이 아님 | `color` 결함(metal_nut 등)은 색·밝기 자체가 결함 신호라 해석에 주의 |
| 가우시안 노이즈, 블러 | 센서 잡음·초점 변화 | 강한 블러는 미세 긁힘을 실제로 지워 버림 → 미검출이 "모델 잘못"만은 아님 |
| JPEG 압축 | 전송·저장 손실 | 학습 데이터는 PNG |
| 회전 | 부품 자세 변화 | 방향·위치가 결함 정의인 유형(**metal_nut `flip`, transistor `misplaced`** — 데이터에서 확인)은 회전·이동이 결함 의미를 바꿈 → 해당 유형은 제외하거나 따로 보고 |
