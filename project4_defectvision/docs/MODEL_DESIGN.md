# 모델 설계

## PatchCore를 주력 모델로 고른 이유
- **정상 데이터만으로 학습:** 제조 라인에서 결함은 드물고 유형이 계속 바뀝니다. 결함 레이블 없이 "정상에서 벗어난 정도"를 재는 방식이 현실 조건에 맞습니다.
- **역전파 없음:** 사전학습 백본 특징 + 최근접 탐색이라 CPU에서도 학습이 몇 분 단위입니다.
- **위치 정보:** 패치 단위 거리가 그대로 anomaly map이 됩니다.
- 참고: Roth et al., *Towards Total Recall in Industrial Anomaly Detection*, CVPR 2022.

## 구현 방식: anomalib 재사용 + 얇은 래퍼
anomalib 2.7.0의 `PatchcoreModel`(Lightning 없이 쓰는 `nn.Module`)을 그대로 쓰고, 래퍼 `PatchCoreDetector`가 다음을 담당합니다.

| 기능 | 이유 |
|---|---|
| 정상 검증셋 기반 임계값 보정 | anomalib Engine의 기본 임계값 방식에 의존하지 않고, 테스트셋을 보지 않는 규칙을 명시적으로 고정 |
| safetensors + JSON 저장 | Lightning 체크포인트(pickle) 역직렬화를 피함 |
| 메모리 뱅크·백본 해시 검증 | 파일 교체나 timm 가중치 버전 변경을 조용히 넘기지 않음 |
| anomalib 지연 import | import에 약 20초가 걸려 API 기동·테스트 시간에 영향 |

확인한 사실 (anomalib 2.7.0 소스, 2026-10-12):
- `train()` 모드의 forward는 임베딩을 `embedding_store`에 쌓기만 하고, `subsample_embedding(ratio)`가 k-center greedy coreset으로 `memory_bank`를 만듭니다.
- 특징 추출기는 forward 안에서 항상 `eval()` + `no_grad`로 돌기 때문에 BatchNorm 통계가 바뀌지 않습니다. 이 성질은 테스트(학습 전후 백본 해시 동일)로 고정했습니다.
- 저장이 필요한 상태는 `memory_bank` 버퍼뿐입니다 (나머지는 고정 블러 커널).

## 기본 설정과 근거
| 항목 | 값 | 근거 |
|---|---|---|
| 백본 | `wide_resnet50_2` (timm 기본 가중치 `racm_in1k`) | PatchCore 논문과 같은 구조. **가중치는 논문의 torchvision ImageNet 가중치와 다름** → 논문 수치와 직접 비교하지 않음 |
| 레이어 | layer2 + layer3 | 중간 수준 특징: 너무 일반적이지도(layer1), ImageNet 분류에 치우치지도(layer4) 않음 |
| 이미지 크기 | 256 | anomalib MVTec 기본값과 같은 수준. CPU 지연시간과 절충 |
| coreset 비율 | 0.1 | anomalib 기본값. CPU 부담이 크면 0.01까지 낮추고 성능 변화를 실측 |
| 이미지 임계값 | 정상 검증 점수의 0.99 분위수 | 정상 기준 오경보율 목표 약 1%. 검증셋이 작으면 사실상 최대값이 되는 한계가 있음 |
| 픽셀 임계값 | 정상 검증 픽셀의 0.999 분위수 | 이진 결함 마스크용 |

## 점수의 의미
- 이미지 점수는 **정규화하지 않은 거리 값**입니다. 0~1 확률이 아니며, 카테고리·모델 버전마다 범위가 다릅니다. 그래서 응답에 항상 임계값을 함께 싣습니다.
- heatmap은 "학습한 정상 패치와 가장 먼 위치"이며, 결함 확정 근거가 아닙니다. 시각화 패널과 UI에 이 문구를 표시합니다.
- heatmap 색 범위는 이미지마다 min–max로 늘리지 않고 모델 기준 고정 범위(검증 최소 점수 ~ 픽셀 임계값×2)를 씁니다. 이미지별 정규화는 정상 이미지에도 붉은 영역을 만들어 오해를 부릅니다.

## 비교 모델 (Phase 5 예정)
- **CNN 지도 분류기:** 정상/결함 레이블이 모두 필요합니다. 공식 분할에서 결함 이미지는 test에만 있으므로, 쓰려면 test를 다시 나눠야 하고 그 순간 PatchCore와 **학습 조건이 달라집니다.** 공정 비교가 아니라 "레이블이 있으면 무엇이 달라지는가"를 보는 참고 실험으로 보고합니다.
- PaDiM: 같은 비지도 조건이라 직접 비교가 가능합니다. 시간이 허락하면 추가합니다.
