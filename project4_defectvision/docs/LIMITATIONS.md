# 한계와 알려진 문제

이 문서는 "무엇을 아직 보장하지 못하는가"를 기록합니다. 해결되면 항목을 지우지 않고 해결 시점과 방법을 덧붙입니다.

## 모델·평가
| 항목 | 내용 | 영향 |
|---|---|---|
| 점수는 확률이 아님 | 이미지 점수는 정규화하지 않은 패치 거리입니다. 카테고리·모델 버전마다 범위가 다릅니다. | API·UI는 항상 임계값을 함께 보여 줍니다. 점수끼리 모델을 넘나들어 비교하면 안 됩니다. |
| heatmap은 추정 | 학습한 정상 패치와 먼 위치를 표시할 뿐, 결함을 확정하지 않습니다. | 패널·UI에 문구를 표시합니다. 최종 판정은 사람 검사자가 합니다. |
| 작은 검증셋 | 정상 검증 이미지는 카테고리당 수십 장 수준입니다. 0.99 분위수 임계값은 사실상 검증 최대값입니다. | 실제 오경보율이 목표(약 1%)보다 클 수 있습니다. 합성 데이터에서도 관찰했습니다 ([EVALUATION.md](EVALUATION.md)). |
| 카테고리별 모델 | 카테고리마다 메모리 뱅크가 따로 있습니다. 처음 보는 제품에는 쓸 수 없습니다. | API는 한 번에 한 아티팩트(한 카테고리)만 서비스합니다. |
| 해상도 | 입력을 정사각형(기본 256 px)으로 줄입니다. 원본 1024 px 기준으로 작은 결함은 몇 픽셀로 줄어듭니다. | 미세 결함 검출 한계. 픽셀 지표도 줄인 해상도에서 계산합니다. |
| 백본 가중치 출처 | timm/Hugging Face에서 받은 ImageNet 가중치를 씁니다. 가중치가 바뀌면 백본 해시 검사로 로드를 거부합니다. | 폐쇄망 배포에는 가중치를 이미지·볼륨에 포함해야 합니다 (Phase 4). |
| 합성 대리 지표 | 하이퍼파라미터 선택에 쓰는 합성 결함은 실제 결함 분포가 아닙니다. | 대리 지표와 test 순위의 일치도를 따로 보고합니다 ([ABLATION_STUDY.md](ABLATION_STUDY.md)). |

## API·시스템
| 항목 | 내용 |
|---|---|
| DB 마이그레이션 없음 | 기동 시 `create_all`로 테이블을 만듭니다. 스키마가 바뀌면 Alembic 같은 마이그레이션 도구가 필요합니다. |
| 인증 | 공유 API 키 하나(`X-API-Key`)뿐입니다. 사용자별 권한·감사 로그는 없습니다. 운영 설정은 키가 없으면 기동을 거부합니다. |
| 추론 직렬화 | 프로세스당 추론 하나씩(잠금). 처리량을 늘리려면 워커 프로세스를 늘려야 하고, 워커마다 모델을 메모리에 올립니다. |
| 결과 이미지 보관 | 원본·heatmap·overlay를 디스크에 무기한 보관합니다. 보존 기간·삭제 정책은 아직 없습니다. |
| PostgreSQL 미검증 | 코드는 SQLAlchemy로 DB 종류와 무관하게 작성했지만, Docker가 없어 PostgreSQL에서는 아직 실행하지 못했습니다 (NOT_RUN). 테스트는 SQLite로 했습니다. |
| SQLite 시간대 | SQLite는 시간대 정보를 저장하지 않아 UTC로 간주해 복원합니다. PostgreSQL은 `timestamptz`를 씁니다. |

## 개발 환경
- 모든 수치는 노트북 한 대(i5-1135G7, Windows 10, CPU)에서 측정했습니다. GPU·Linux 수치는 측정하지 않았습니다.
- Node.js·Docker가 없어 프론트엔드·컨테이너는 아직 구현·검증하지 못했습니다.
