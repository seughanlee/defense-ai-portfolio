# 용어 설명

이 프로젝트 문서에 나오는 전문용어를 한두 줄로 풀었습니다. 숫자 지표는 **모두 0~1 범위이고 1에 가까울수록 좋습니다** (지연시간·메모리는 작을수록 좋음).

## 검출 성능 지표
| 용어 | 뜻 | 읽는 법 |
|---|---|---|
| **AUROC** (image AUROC) | 결함 이미지 하나와 정상 이미지 하나를 무작위로 골랐을 때, 모델이 결함 쪽에 더 높은 점수를 줄 확률 | 1.0 = 완벽하게 구분, 0.5 = 동전 던지기. 임계값과 무관한 "순위 매기기 실력" |
| **AP** (Average Precision) | 점수 높은 순서로 검사했을 때, 결함을 찾아 가는 동안 경보의 정확도 평균 | 결함이 드물수록 AUROC보다 엄격. 양성 비율이 다르면 카테고리끼리 비교 불가 |
| **pixel AUROC** | AUROC를 이미지가 아니라 **픽셀** 단위로 계산한 값 | heatmap이 결함 픽셀을 정상 픽셀보다 뜨겁게 칠하는지 |
| **PRO** (Per-Region Overlap) | 결함 영역 **하나하나**에 대해 heatmap이 그 영역을 얼마나 덮었는지의 평균 | 큰 결함 하나가 작은 결함 여러 개를 가리지 못하게, 영역마다 같은 비중을 줌 |
| **AUPRO** | 정상 픽셀 오경보율(FPR)을 0에서 30%까지 늘려 가며 그린 PRO 곡선의 면적을 0~1로 정규화한 값 | "오경보를 적당히 허용할 때 작은 결함까지 위치를 잘 짚는가". MVTec 논문이 정의한 지표 |
| **IoU** | 예측 결함 마스크와 정답 마스크의 겹친 넓이 ÷ 합친 넓이 | 임계값 하나에서의 위치 정확도 |
| **Precision / Recall / F1** | Precision = 이상 판정 중 진짜 결함 비율, Recall = 진짜 결함 중 잡아낸 비율, F1 = 둘의 조화평균 | 임계값에 따라 바뀌므로 **항상 임계값과 함께** 적음 |
| **FPR** (오경보율) | 정상 중 이상으로 잘못 판정한 비율 | 라인에서는 재검사 비용으로 이어짐 |
| **Confusion matrix** | 정상/이상 × 맞음/틀림 네 칸의 건수 (tn, fp, fn, tp) | fn(놓친 결함)이 유출 위험 |

## 운영 지표
| 용어 | 뜻 |
|---|---|
| **P50 / P95 지연** | 요청 100건을 빠른 순으로 줄 세웠을 때 50번째 / 95번째 요청의 처리 시간. P95는 "거의 최악" 지연 |
| **처리량** (throughput) | 초당 처리 이미지 수 |
| **최대 메모리** (peak RSS / working set) | 프로세스가 실행 중 가장 많이 쓴 물리 메모리. 서버·컨테이너 메모리 크기를 정하는 근거 |

## 모델 용어
| 용어 | 뜻 |
|---|---|
| **이상탐지** (anomaly detection) | 정상만 배운 뒤 "정상과 다른 것"을 찾는 방식. 결함 레이블이 필요 없음 |
| **PatchCore** | 이미지를 작은 패치로 나눠 정상 패치 특징을 저장해 두고, 새 이미지의 패치가 저장된 것과 얼마나 먼지로 이상 점수를 매기는 방법 |
| **백본** (backbone) | 특징을 뽑는 데 쓰는 사전학습 CNN (예: wide_resnet50_2). 여기서는 다시 학습하지 않음 |
| **특징 레이어** (layer2, layer3) | 백본의 중간 단계 출력. 앞쪽은 질감, 뒤쪽은 형태에 가까운 정보 |
| **메모리 뱅크** (memory bank) | 정상 이미지에서 뽑은 패치 특징 모음. PatchCore의 "학습 결과"가 이것 |
| **Coreset / k-center greedy** | 메모리 뱅크를 줄이는 방법. 서로 가장 멀리 떨어진 대표 패치를 차례로 골라, 적은 수로 전체를 고르게 덮음 |
| **Anomaly map / heatmap** | 픽셀마다 이상 정도를 색으로 칠한 그림. **모델의 추정**이지 결함 확정이 아님 |
| **임계값** (threshold) | 점수가 이 값을 넘으면 이상으로 판정. 여기서는 정상 검증 이미지 점수의 99% 지점으로 정함 |
| **분위수** (quantile) | 값을 줄 세웠을 때 특정 비율 지점의 값. 0.99 분위수 = 99%가 그 아래 |

## 실험 설계 용어
| 용어 | 뜻 |
|---|---|
| **Ablation study** | 설정 하나씩만 바꿔 가며 각 요소가 결과에 주는 영향을 재는 실험 |
| **사전 등록** (pre-registration) | 결과를 보기 전에 실험 계획과 선택 규칙을 고정해 해시로 기록하는 것. 결과에 맞춰 규칙을 바꾸는 것을 막음 |
| **데이터 누수** (leakage) | 평가용 데이터가 학습이나 설정 선택에 섞여 성능이 부풀려지는 것 |
| **대리 지표** (proxy) | 진짜로 재고 싶은 것(실제 결함 성능)을 직접 못 쓸 때 대신 쓰는 지표. 여기서는 검증 이미지 위의 합성 결함 |
| **Spearman 순위상관** | 두 지표가 설정들의 순위를 얼마나 같게 매기는지 (-1~1, 1 = 순위 일치) |
| **부트스트랩** (bootstrap) | 가진 데이터에서 복원 추출을 반복해, 통계값이 표본에 따라 얼마나 흔들리는지 추정하는 방법 |

## 시스템 용어
| 용어 | 뜻 |
|---|---|
| **Liveness / Readiness** | Liveness = 서버 프로세스가 살아 있음. Readiness = 검증된 모델까지 올라와 실제 요청을 처리할 수 있음 |
| **Demo Mode** | 모델이 준비되지 않은 상태. 검사 요청을 거부하고 가짜 점수를 만들지 않음 |
| **CI** (Continuous Integration) | 코드를 올릴 때마다 서버에서 린트·테스트를 자동으로 돌리는 것 (GitHub Actions) |
| **린트** (lint, ruff) | 실행 전에 코드의 문법 문제·안 쓰는 import 같은 실수를 자동으로 찾는 도구 |
| **safetensors** | 텐서만 담는 파일 형식. pickle과 달리 열 때 임의 코드가 실행되지 않음 |
| **SHA-256 해시** | 파일 내용의 지문. 한 바이트만 바뀌어도 완전히 달라져 변조·교체를 잡아냄 |
